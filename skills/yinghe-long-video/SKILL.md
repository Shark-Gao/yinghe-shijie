# 硬核长视频工坊

## 定位与边界

本技能负责“故事完整、源片等长、适合 B 站或完整观看”的版本。它与 `yinghe-short-video` 隔离：长视频先保证问题、证据、机制和结果完整，短视频再从长视频或源片中拆出独立答案，不让短视频时长反过来删掉长视频必要内容。

只处理用户拥有或获准复用的源视频。不得移除源片版权标识，不得把他人素材包装成原创拍摄，也不得自行上网寻找替代画面填补源片缺口。

## 输入与输出

输入通常包括：

- 原始 MP4；
- SRT、VTT 或 TXT 字幕；
- 可选的章节、选题卡和剪辑计划。

### 源视频与字幕的独立交付规则

- 源视频通常不自带中文字幕；用户提供的 SRT、VTT 或 TXT 默认视为独立字幕文件，不能假定已经内嵌在 MP4 中。
- 正式 MP4 默认保留源片画面和音轨，不烧录中文字幕；中文字幕作为旁车 SRT 单独交付，并与 MP4 放在同一最终目录。
- 只有用户明确提出“烧录字幕”“硬字幕”“把字幕合成到画面”等要求时，才允许使用 FFmpeg 或剪映把字幕渲染进 MP4；此时仍要保留一份独立 SRT。
- 生成前必须检查源 MP4 的字幕流和画面抽帧，确认“MP4 是否已有中文字幕”与“字幕文件是否另行提供”；不以文件名、上一条任务或字幕时间线自行推断。
- 用户明确不需要解说音频时，跳过 TTS/MP3 生成，但仍按本技能交付字幕文件、字幕时间线、画面注释、剪辑计划、发布包装和不含中文字幕烧录的 MP4。

计划文件放在 `outputs/long/`，音频生成过程可以使用 `outputs/audio/`。正式交付目录固定为 `videos/exports/长视频/<主题>/`，但必须区分“内部制作资产”和“用户取件文件”：除非用户明确索要工程文件，最终回复只交付一个无 BGM 的中文解说 MP4 和一个句子级中文 SRT；TTS 分段、备用音频、双语 SRT、时间线 JSON、分段时长 JSON、画面注释、封面、发布包装和验收记录留作内部资产，不在最终回复中混列为取件文件。这里的“内部资产”是指不一定全部在最终回复逐项展开，不是指可以不生成；长视频封面仍然必须生成并归档。临时 TTS 分段、日志、联系表、抽帧和测试文件继续留在 `outputs/`。

长视频内部制作通常应生成：

- 等长中文解说时间线 JSON；
- 中文解说 MP3；
- 中英双语中文解说 SRT；
- 中文字幕直读时间线和直读 MP3；
- 等长文本注释 JSON；
- 有源视频时的自动混音 MP3；
- 完整长视频 MP4 和独立旁车 SRT（默认不烧录字幕）；
- 一份通用发布包装 JSON，包括标题、带话题的完整简介和封面文件映射；
- 三种尺寸的封面：横版 `16:9 / 1920x1080`、`4:3 / 1440x1080`、竖版 `3:4 / 1080x1440`。

默认用户取件保留以下正式资产：

- `<主题>_长视频配音版.mp4`：保留源片画面，使用中文解说作为主声道，默认不加入 BGM、不烧录字幕；
- `<主题>_中文字幕.srt`：只含中文，按完整句子拆分，句子过长时只换行、不拆成碎片。
- 三张封面：`16:9`、`4:3`、`3:4`，使用对应安全构图；
- 标题、完整简介和话题，必须在最终回复中直接给出；发布包装 JSON 可作为可选归档文件。

如果用户明确要求剪辑工程、纯人声 MP3、自动混音 MP3、时间线、画面注释、封面或发布包装，再单独提供对应内部资产。

## 正式交付目录与发布包装

- 完成验收后，把正式 MP3、SRT、时间线 JSON、分段时长 JSON、画面注释 JSON 和封面移动或复制到 MP4 所在目录；三张封面必须与 MP4 同目录，并沿用短视频规则命名为 `<主题>_封面_16x9_设计版.png`、`<主题>_封面_4x3_设计版.png`、`<主题>_封面_3x4_设计版.png`，不能只留在项目根目录的 `covers/` 下；`outputs/audio/` 只作为生成中间目录，不作为用户最终取件路径。
- 每条长视频默认必须生成一套军事向或女性向三张原创封面；未明确跳过时，缺少任一比例都视为未完成，禁止进入正式交付目录或在最终回复中宣称已完成。
- 交付前必须逐项核对 `cover_style`、`cover_title`、`cover_headline`、`cover_subhead`、`cover_assets` 和 `cover_sizes`；三张图片必须真实存在、比例和尺寸正确、文字后期叠加且通过安全区检查。
- 每条长视频必须产出一个通用标题、一份可直接粘贴的完整简介和一组话题。标题优先突出冲突、结果、规模、成本、稀缺性或现实影响；简介说明观众将看懂什么，结尾固定附 `3–5` 个与内容直接相关的话题标签。
- 最终回复必须把“标题”“简介”“话题”三项直接写出来，使用可复制的纯文本段落，不能只给发布包装 JSON、文件链接或提示用户去文件里查找。简介末尾保留完整话题标签，另将同一组话题单独列出；如有平台版本，则按平台分别直接输出标题、简介和话题。
- 长视频封面设计与 `yinghe-short-video` 保持同一套视觉规范，不再使用源片截图、成片画面截图或只套模板的封面；先按 `cover_style` 选择军事向或女性向视觉系统，每条长视频默认生成一套三张原创底图，再统一叠加中文标题。
- 底图使用原创图像生成或项目允许的原创视觉素材，底图不得出现模型生成的中文、Logo、水印、旗帜或无关文字；标题必须使用 `skills/yinghe-short-video/scripts/add_cover_title.py` 等工具后期叠加，确保文字准确可读。
- `military`：16:9 主体放左侧、右侧留深色标题区；4:3 单独构图，主体放左侧或左下方；3:4 主体集中在下半部、标题放在上方或中央安全区。使用深蓝黑、钢铁灰、青蓝或克制橙色，主体优先为武器、装备、地图、剖面、雷达轨迹、舰船、战机、导弹或直接相关军工场景。
- `female`：使用深海军蓝、薄荷绿/青绿色和珊瑚色的温暖非写实编辑插画；16:9 主体在左侧或左下、右侧留标题区，4:3 单独构图，3:4 主体在下半部、顶部留标题区。主体围绕稳定发挥、情绪、关系、亲子或女性成长，标题突出具体问题和可验证的行动收益。
- 两种风格都必须独立构图、保留安全区、后期叠加准确中文，不生成模型内置中文、Logo 或水印。主标题控制在 `4–6` 个汉字，副标题控制在 `6–8` 个汉字，不让标题压住主体或贴边。
- 发布包装建议保存为 `<主题>_发布包装.json`，至少包含 `general_title`、`general_description`、`hashtags`、`cover_assets` 和 `cover_sizes`；如另有平台版标题，再增加 `platform_variants`，不要用平台差异替代通用版本。
- 标题、简介和封面承诺必须能由口播、字幕或画面证据支撑；不写“全网第一”“绝对领先”等无法核验的绝对化结论，不使用与军事伤亡、灾难和受害者无关的猎奇热梗。

优先复用：

- `../generate-narration-audio/SKILL.md` 及其脚本，生成等长解说和音频资产；
- `../yinghe-short-video/references/edit-plan-schema.md`，编写剪辑计划；
- `../yinghe-short-video/scripts/prepare_review_assets.py`，检查源片画面和字幕；
- `../yinghe-short-video/scripts/validate_preflight_review.py`，执行成片前内容预审；
- `../yinghe-short-video/scripts/produce_short_video.py` 和 `build_short_video.py`，在计划兼容时复用现有 FFmpeg 渲染器。脚本名称虽然含 `short`，但不能因此把长计划改成短视频节奏。
- `scripts/retime_timeline_to_tts.py`，把 TTS 分段实测时长转换成实际配音对齐时间线；未完成此步骤，不得生成正式字幕或验收 MP4。

## 长视频编辑卡

写口播前必须先建立编辑卡：

```text
主赛道：军事武器 / 武器系统 / 作战机制
普通人问题：观众为什么要关心？
核心答案：这条视频最终让观众明白什么？
前2秒钩子：第一句和第一画面是什么？
5—10秒承诺：最晚什么时候交付答案？
章节结果：每章解决什么子问题？
情绪变化：观众看完后从什么判断变成什么判断？
系列归属：下一条可以接什么？
事实状态：已核实事实 / 来源分析 / 合理推测
```

一条长视频可以有多个章节，但必须围绕一个总问题。每章都要有“问题—解释—证据—阶段性结论”，不能把源片字幕按时间顺序直接拼成中文旁白。

## 解说文案规则

解说必须重写，不做逐句直译：

- 0–2 秒给出冲突、结果或反常识；
- 2–5 秒用地图、装备、结构或数据画面证明问题存在；
- 5–10 秒交付总答案或答案方向；
- 中段按“机制 → 证据 → 后果”推进章节；
- 结尾回答现实影响、限制条件，并提出具体的系列承接问题。

语言使用自然中文纪录片口吻。普通句子约 15–25 个汉字，每段通常 3–8 秒、1–2 句话；专业名词先解释功能，再补型号或英文名。数字改成适合朗读的中文，删除源片赞助、频道宣传和无关行动号召。

## 中国表达与网络热梗

长视频可以加入中国歇后语、成语和适度网络表达，但必须服务于解释，不得把纪录片写成段子合集：

- 20–30 分钟长视频通常控制在 3–6 处；每章最多 1–2 处，没有自然位置就不用。
- 优先放在开头钩子、章节转折、阶段性结论或机制比喻处；事实、数据、型号和时间线句子保持直白。
- 适合军事武器、作战和后勤语境的表达示例：`泥菩萨过江——自身难保`（自保能力不足）、`远水解不了近渴`（支援距离远或响应慢）、`兵马未动，粮草先行`（后勤先于作战）、`巧妇难为无米之炊`（资源或弹药不足）、`牵一发而动全身`（武器系统或供应链的连锁影响）、`一着不慎，满盘皆输`（单点失误带来全局代价）、`杯水车薪`（投入不足）、`唇亡齿寒`（相互依赖）。不要为使用歇后语而强行改写事实。
- 可少量使用听众已经熟悉的网络表达，如 `卡脖子`、`上强度`、`补课`、`破防`。只有当它准确描述供应瓶颈、局势升级、能力追赶或防线/心理受到冲击时才使用；不追逐短命热梗，不依赖 `家人们`、`震惊`、`太离谱了`、`看到最后` 等低信息量话术。
- 战场伤亡、真实灾难、严重人道后果和具体受害者段落不使用搞笑梗；可以使用沉稳成语，但不调侃现实苦难、国家民族或群体。
- 通常采用“一个表达 + 一句白话解释”，例如：“这条供应链像泥菩萨过江，自身难保——一旦关键磁材断供，先受影响的不是武器性能，而是持续生产和维修。”
- 保持长期可听性。验收时删掉不自然、过时、与画面无关或会让观众误解立场的表达。

## 中国视角与民族自豪感

涉及中国、台海、南海、对华军事竞争、中国军工或中国武器发展时，默认以中国的安全、武器能力、军工制造、普通人现实利益和长期国家利益为主要观察视角，允许明确表达对中国武器研发、制造能力、装备建设和组织协同的肯定，形成克制而有依据的民族自豪感：

- 先回答“中国做到了什么、解决了什么问题、还面临什么限制”，再展开国际比较；优先使用可核验的产量、速度、成本、覆盖范围、技术指标、产业链和实际应用作为自豪感的落点。
- 涉及争议事件或国家安全议题时，区分已核实事实、中国官方或权威机构公开表述、来源分析和合理推测。中国立场可以更鲜明，但不能用口号代替证据，也不能把未证实消息写成确定事实。
- 与其他国家比较时，按照同一指标、同一时间和同一任务口径比较，不使用“全面碾压”“无敌”“遥遥领先”等无法由画面和数据支撑的绝对化结论；需要批评不足时，采用“问题—原因—改进空间”的建设性表达。
- 不把中国立场写成对其他国家、民族或普通人的侮辱，不使用民族歧视、战争煽动和幸灾乐祸式表达。民族自豪感应建立在真实成果、具体人物和长期积累上，而不是贬低他者。
- 适合使用“这不是简单的单项性能，而是完整军工体系带来的持续能力”“真正值得自豪的，不只是某一件装备，而是把它稳定造出来、用起来、维护下去的体系”等总结句，但必须与本片证据对应。

军事武器、战争背景和地图内容必须区分“已核实事实”“来源分析”和“合理推测”。不能把演习、概念方案、模型演示或分析者判断写成已经发生的战果或确定计划。每段口播都要能找到对应的视觉证据，不用语义无关的漂亮镜头填空。

20–30 分钟视频通常使用约 50–80 个自然口播段，先按每 30 秒 80–110 个中文字估算，再以实际 TTS 时长重排。最终段落数量由章节密度决定，不为凑数量添加空话。

## 配音与混音默认值

项目男性向规则优先于通用技能默认值：

- provider：`edge`；
- voice：`zh-CN-YunyangNeural`；
- rate：`+0%`，男性向长视频默认保持原始语速，不自动加速或减速；
- 默认不添加 BGM，不填写 `background_music`；
- 默认关闭会干扰解说的源片人声；需要保留机械声、爆炸声或环境声时，使用自动压低并记录源声音量。

只有用户明确指定语速时，才允许修改 `rate`，并在计划中记录指定值；用户未指定时始终使用 `+0%`。声音、BGM 或原声保留仍按用户要求执行并在计划中记录。

每段 TTS 必须记录实际时长，不能用计划窗口假装音频时长。生成字幕和解说时间线时，必须使用 `render_timeline_tts.py` 生成的分段时长清单，并运行 `scripts/retime_timeline_to_tts.py` 重建实际配音对齐时间线；保留 `visual_start`、`visual_end` 作为画面窗口，把 `start`、`end` 用作实际音频和字幕窗口。不得直接把计划中的 30 秒段落复制成字幕时码。

如果实测音频超过该段画面窗口，必须缩短或重写该段文案、重新生成 TTS，或明确延长画面窗口；正式交付不得允许最后一句被 `-t` 截断，也不得用 `--allow-truncated` 掩盖问题。重新生成后必须核对 `truncated_segments` 为空。

如果实测音频明显短于源片总时长，不能只把字幕提前来制造“同步完成”的假象。应优先补写必要的承上启下和证据解释，让源片长度内连续口播；如果内容本身不需要等长，则改为较短的完整版本并同步缩短画面。任意连续无口播区间原则上不超过 `0.8` 秒。

## 画面—解说同步硬规则

本项目曾出现过“解说在约 31 秒说到手电筒，原画面约 48 秒才出现灯光示意”的问题。根因不是单纯的全片语速，而是把一个较长时间窗误当成了内部语义已经对齐：同一段配音里，名词和动作的先后顺序与原片画面发生了漂移。以后必须把“段落时长对齐”和“段落内部语义对齐”分开验收。

- 不得只按固定 `25` 秒或 `30` 秒切段就认定已经同步。只要一个时间窗内发生了画面转场、示意图切换、装备/动作变化，就必须按视觉变化继续拆分，或在同一段内明确安排对应句子的先后顺序。
- 写解说前先建立“画面锚点表”。每个关键装备、动作、数字、术语和比喻至少记录 `anchor_text`、`visual_start`、`visual_end`、`source_evidence`；例如“手电筒/探照灯”必须对应原片灯光示意真正出现的时间，而不是只对应这一章的大致时间窗。
- 画面锚点表必须写入计划的 `visual_alignment` 字段，并设置 `required: true`。每个锚点还必须指定 `segment_id`；默认 `match_mode: segment_start`，要求锚点句独立成为一个 TTS 段并从该段开头说出，禁止在 25 秒长段内部按字数猜测锚点位置。
- 同一锚点只能在对应画面附近首次出现。不得为了填满前一段，把后面才出现的名词提前说；也不得把多个视觉变化压缩成一串与画面顺序不同的解释。
- TTS 生成后，必须用实际配音时间线和句子级 SRT 复核锚点。锚点句的起始时间与对应画面起始时间原则上相差不超过 `1` 秒；超过 `1` 秒就重写、拆段或调整句序，不得只靠全片加速、减速或裁切 MP4 掩盖问题。
- 成片编码前至少抽查每个锚点的“画面出现前、画面出现时、画面出现后”三个位置，并试听锚点词所在句子；发现一个关键锚点错位，整条成片不得进入正式交付。
- `preflight_review.revision_notes` 必须记录本次锚点抽查范围和结论；正式验收除 `truncated_segments = []`、连续空档不超过 `0.8` 秒外，还必须运行 `skills/yinghe-long-video/scripts/validate_visual_alignment.py`，生成画面锚点验收报告并得到 `status = passed`。手工填写 `alignment_anchors = passed` 不能替代脚本验收。
- 连续空档阈值统一由计划的 `visual_alignment.max_gap_seconds` 控制，默认值为 `0.8` 秒；缺少该字段时验收器也按 `0.8` 秒阻断，不得通过补静音、整段加速或事后裁切掩盖空档。

## 文案成稿审阅门

每次完成初稿或大幅修改文案后，进入配音前必须逐段审阅并记录结果；审阅未通过，不得生成 MP3 或 MP4：

- 通顺度：逐段朗读，检查口语是否自然、逻辑是否连贯、是否有病句、重复、硬塞歇后语或为凑时长留下的尾句；
- 题意与画面：每段都要回答总问题、推进章节或解释画面证据，不把来源分析、模型预测和编辑判断写成已发生事实；
- 画面锚点：逐项核对装备、动作、比喻、数字和关键术语的首次出现时间；不能用“同一段里最终会出现”替代实际起始位置；
- 技能要求：检查 2 秒钩子、5–10 秒答案方向、章节因果、事实边界、中国视角、克制的民族自豪感和适度网络表达；
- 连续口播：源片静音或关闭原声时，补写必要的承上启下解释；逐段使用实测 TTS 时长复核覆盖范围，任意连续无口播区间原则上不超过 `0.8` 秒，不用静音凑等长；
- 记录方式：将本次审阅范围、修改点和复核结论写入长视频计划的 `preflight_review.revision_notes`，或保存独立审阅记录。

## 标准制作流程

1. 确认源视频和字幕的授权、文件位置与总时长。
2. 运行 `prepare_review_assets.py`，检查源片联系表和字幕提示；先确认章节和画面证据，再写解说。
3. 建立编辑卡和长视频计划，保持源片 16:9 和主要章节；除非用户要求，不裁成 9:16。
4. 使用 `generate-narration-audio` 的 `render_timeline_tts.py` 或 `render_cosyvoice_timeline.py` 生成中文解说和分段时长清单。随后运行 `scripts/retime_timeline_to_tts.py`，以实测音频窗口生成实际配音对齐时间线，再由该时间线导出只含中文的 SRT。最终字幕必须使用 `split_srt_cues.py --sentence-only --max-chars 20`：按句号、问号、感叹号和分号拆成一句一条；长句只做显示换行，不把一句话硬切成多个字幕条目。默认不向用户交付整段版、双语版或按字数硬切版 SRT。
   - 如果计划启用了 `visual_alignment.required`，必须在正式合成前由 `produce_short_video.py` 自动运行 `retime_timeline_to_tts.py` 和 `validate_visual_alignment.py`；任一锚点失败就停止生成 MP4。
5. 在首次渲染前填写 `preflight_review`，核对事实边界、总问题、章节答案、开头钩子、画面证据、标题和简介；运行 `validate_preflight_review.py`。
6. 完成“文案成稿审阅门”，记录通顺度、题意与画面、技能要求和连续口播覆盖四项结果；任一项未通过，不得生成 MP3 或 MP4。
7. 优先用现有 `produce_short_video.py --plan <long-plan.json>` 自动生成配音并调用共享渲染器；如果长计划需要剪映中的章节、原声分段或手工调整，则把已生成的 MP3、SRT 和注释交给剪映完成最终合成。默认渲染 MP4 不烧录字幕；只有计划中明确记录用户要求硬字幕时才启用字幕滤镜或剪映字幕合成。
8. 对成片做完整观看和试听：核对章节顺序、画面—口播对应、音频连续性、字幕时码、源片声是否压住解说、片头片尾是否有无意义空白；另外逐项抽查画面锚点，确认关键名词和动作没有提前或延后到错误画面。
9. 先把正式 MP3、SRT、解说时间线 JSON、分段时长 JSON、画面注释 JSON、三张按短视频命名规则命名的封面和发布包装 JSON 归档到 MP4 同目录，再清理临时 TTS、联系表、测试文件和中间 JSON；不得把唯一交付资产留在 `outputs/audio/` 或项目根目录的 `covers/` 下。
10. 运行最终交付清单：确认三张封面、发布包装 JSON、MP4、SRT 和必要音频均在正式目录；任一封面缺失、尺寸错误或未通过视觉检查，都必须停止交付并补齐。

## 长视频与短视频的关系

长视频输出一个内容完整的主版本；抖音、快手和小红书版本再按独立问题、自然章节边界或平台限制拆分。没有自然边界时，不为满足 30–90 秒而硬切结尾或删掉必要证据。

短视频拆分时重新写开头、标题、结尾和简介，并重新执行短视频预审；不得把长版 SRT 或长版节奏直接当作短版交付。

## 完成标准

- 长视频回答一个明确总问题，章节之间有因果关系；
- 5–10 秒内交付总答案方向；
- 每段解说都有视觉证据或明确的解释功能；
- 画面锚点逐项通过：关键名词、动作、数字和比喻与对应画面起始时间相差不超过 `1` 秒；
- 事实、来源分析和推测边界清楚；
- 口播、字幕、画面和章节没有错位；
- 字幕显示通过可读性验收：中文解说按实际 TTS 时长和自然停顿拆成多条时间字幕，单条目标约 `20` 个汉字且最终最长不超过 `20` 个汉字，原则上不少于 `1` 秒，避免三行长句、单字闪现和字幕末尾标点；
- 字幕、解说时间线和 MP3 通过实测时长复核：`truncated_segments` 为空，字幕最后时码不超过视频时长，音频结束后不残留计划窗口字幕；
- `alignment_anchors = passed` 只在画面锚点脚本报告 `status = passed` 后成立，且已经抽查关键锚点前后画面与实际试听；
- 文案已通过通顺度、题意与画面、技能要求、连续口播覆盖四项审阅，并在 `preflight_review.revision_notes` 留有记录；
- 输出保持完整故事，不以任意固定时长为目标；
- 男性向长视频默认使用 Edge `zh-CN-YunyangNeural` `+0%`，不自动修改语速，无 BGM；
- MP4 默认不烧录中文字幕；独立 SRT、正式音频（如用户需要）、时间线、画面注释、发布包装和三种尺寸封面均位于同一最终交付目录；
- 若用户跳过解说音频，计划必须记录 `audio_generation.status = skipped_by_user` 及剪映人工配音说明，不得创建伪造或占位 MP3；
- 发布包装包含一个通用标题、一份结尾带 `3–5` 个话题标签的完整简介，以及 `16:9`、`4:3`、`3:4` 三张可用封面；三张封面均应是独立构图的原创底图加后期准确文字，不得以源片截图或横版硬裁替代；
- 除非用户明确要求跳过封面，否则任何长视频计划都不得以“用户没有再次提醒”为理由省略封面；“推荐视频流程默认不生成封面”的规则只适用于推荐记录，不适用于长视频制作。
- 最终回复中直接交付可复制的“标题 / 简介 / 话题”三件套；有平台版本时逐个平台输出，不能只交付 JSON 文件路径；
- 通过预审和技术验收后，才将 MP4 放入 `videos/exports/长视频/`。
