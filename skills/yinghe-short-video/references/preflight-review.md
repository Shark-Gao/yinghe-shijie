# 成片前内容审查

每个短视频计划在第一次渲染前必须完成一次内容预审。预审由 Codex 自动执行，不等待用户提醒，也不能把首次内容审查推迟到 MP4 生成后。

## 必查项目

1. **立场与事实**
   - 解释角度落到装备、地理、技术、后勤、产业或现实影响，不用政治站队替代解释。
   - 区分核实事实、来源分析和推断；演习、模拟命中、推演结果不能写成真实战果。
   - 不使用侮辱、民族对立、幸灾乐祸或未经支持的“碾压”“打脸”“必胜”等表达。
2. **情绪价值**
   - 明确观众原先容易产生的判断，以及看完后获得的认知变化、紧张感、反转、规模感或现实关联。
   - 情绪必须由事实、机制、后果或对比产生，不能只用“震撼”“离谱”等空洞形容词。
   - 结尾必须交付答案、后果或下一期的具体问题，不能只留下悬念。
3. **冲突与钩子**
   - 选题、标题和开头必须共享同一个具体问题。
   - 0–2 秒出现冲突、结果或强画面；5–10 秒内给出核心答案或明确答案方向。
   - 冲突至少有一组可解释的对立关系，例如小与大、隐蔽与探测、成本与效果、规模与效率；不能只靠夸张措辞制造冲突。
4. **脚本与画面**
   - 每个口播段都有对应的源片画面或图示证据。
   - 标题、封面文案、口播、四个平台简介指向同一个问题、答案和事实边界。
   - 开头承诺、核心答案、结尾结果和封面文案互相兑现。
5. **安全与发布边界**
   - 识别需要归因、保守表述或补充来源的说法，并在口播或简介中处理。
   - 不把攻击、命中或战争伤害包装成无条件值得兴奋的结果；军事内容优先讲机制、能力边界和现实影响。

## 预审结果

将结果写入编辑计划的 `preflight_review` 字段。只有全部项目通过，才能把 `status` 设为 `passed`：

```json
{
  "preflight_review": {
    "status": "passed",
    "review_scope": "content_before_render",
    "one_line_question": "普通观众真正想知道什么？",
    "one_line_answer": "这条视频最终给出的明确答案是什么？",
    "conflict": "这条内容的核心对立关系是什么？",
    "emotional_value": "观众看完后改变了哪个判断或获得了什么具体感受？",
    "checks": {
      "position_and_fact": "pass",
      "emotional_value": "pass",
      "conflict_and_hook": "pass",
      "answer_timing": "pass",
      "visual_evidence": "pass",
      "title_script_consistency": "pass",
      "safety_and_attribution": "pass"
    },
    "risk_notes": [],
    "revision_notes": []
  }
}
```

如果任一项不通过，先修改问题、答案、口播、标题、简介或画面计划，再重新执行预审；预审未通过时禁止运行 `produce_short_video.py`。渲染完成后只做技术验收和文件完整性检查，不把立场、情绪价值、冲突点等内容规则留到成片后首次判断。
