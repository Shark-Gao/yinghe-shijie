# 预检、成片验收与返修规范

## 渲染前

运行：

```powershell
python "L:/workspace/yinghe-shijie/skills/yinghe-short-video/scripts/validate_preflight_review.py" --plan "<plan.json>"
```

预检必须确认：

- 前2秒看见异常，前5秒知道危险，前10秒知道观看理由。
- 标题、封面、开头、口播/注释和结尾承诺同一结果。
- 故事卡只有一个核心问题和一条独立冲突链。
- 内容完成度与分发潜力已分别评分。
- 解说紧贴画面；原剧关键引用没有被解说打断。
- 片段不重叠、不重复，源时间边界完整。
- 原创表达承担主体，注释没有退化成逐句字幕。
- 注释密度与剧情类型匹配。
- 注释和封面元数据齐全。

## 四道交付门禁

按以下顺序执行，并在 `delivery_manifest` 和 `review_record` 中记录结果：

1. **生成前清单**：列出两版 MP4、中文解说 MP3/SRT、注释 JSON/SRT、两份计划、三种正式封面、三种主页缩略图测试图和平台包装的目标路径；同时在计划中填写 `primary_version`。
2. **渲染后文件校验**：逐项确认文件存在、大小正常、扩展名正确；用 `ffprobe` 检查 MP4 实际时长和音视频流，用注释校验脚本检查 JSON，并确认注释 JSON/SRT 互相一致。
3. **实际复核**：完成下方成片、音频、字幕、画面、封面和缩略图检查；不能用“命令曾经启动”或“MP4 能播放”代替检查结果。
4. **最终状态**：只有所有项目均为“通过”才标记“已完成”；任一项目未执行、命令中断、文件缺失或结果不明，必须标记“待核验/待返修”。

## 成片复核顺序

1. **实际时长和流**：以 `ffprobe` 的实际 MP4 时长和视频/音频流为准，不以计划预计时长代替。
2. **源边界**：逐段核对 `source_start`、`source_end` 和源字幕；对白完整，动作有起势、执行和紧接着的后果。
3. **成片对应**：抽检开头、每个切点、对白结束点、解说开始点、注释出现点和结尾，确认源时间、成片时间、字幕、原声和解说对应。
4. **音频停讲**：从实际 TTS 时长清单计算相邻段间隔；普通停讲低于1.5秒时返修。确认停讲期间是计划内原声或明确静音，不是误以为中文解说仍在连续播放。
5. **画面质量**：抽帧或完整观看，确认没有黑屏、冻结帧、错轴、突然静音、原声遮挡关键台词或解说晚于画面信息。
6. **注释一致性**：注释 JSON、旁车 SRT 和成片时间轴一致，注释未烧录；纯原声版不出现中文配音。
7. **封面大图**：三种封面无残留类别标签、错字、Logo、水印和不相关文字；标题没有压住道具或关键手部。
8. **主页缩略图**：把三种封面缩小到账号视频列表的显示尺寸，检查3秒内是否能读出道具、主标题和冲突；记录“可读/需返修”。
9. **账号网格一致性**：与近期视频并排查看，确认统一的深色宫廷、白字、蓝线和道具识别系统仍然成立，不因单条封面追求花哨而破坏账号识别度。
10. **交付清点**：确认 MP4、MP3/SRT、注释 JSON/SRT、两份计划、三种封面、平台标题、完整简介和话题齐全。

将三种主页缩略图测试图放入输出目录的 `成片核验` 子目录，并在验收记录中写明三种比例的结果。没有近期账号主页截图时，必须注明“账号网格一致性未核验”，不得把该项默认为通过。

## 返修规则

任何一项失败，都必须同步调整计划、旁车、注释或封面，并重新渲染受影响的成片。不能只修改计划文件后把旧 MP4 标记为完成。返修后重跑预检、注释校验、实际时长检查、停讲检查、画面抽检和缩略图检查；未通过时标记为“待返修”。如果 QA 命令被中断，保留已完成项，但所有未确认项都必须回到“待核验”，不能直接进入正式交付。

## 发布后复盘入口

成片验收通过不等于复盘完成。发布后必须按 [`post-publish-review.md`](post-publish-review.md) 记录平台、发布时间、包装版本和核心数据，并注明当前视频属于“播放规模型”“观看效率型”还是“互动讨论型”。
