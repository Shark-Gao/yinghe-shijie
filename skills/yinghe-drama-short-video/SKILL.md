# 电视剧剧情注释短视频工坊

将有权使用的电视剧、电影或短剧素材剪成以原剧对白、环境声和动作声为主体的短视频。中文信息只通过画面上的一行“接下来剧情简介”传递，不生成中文解说音频，不压低或替换原剧声音，不把屏幕文字做成主标题加副标题卡片。

每条剧情先确定：一个普通观众能理解的人性问题、一个前 2 秒冲突提示、一个 5—10 秒内通过画面或注释交付的阶段性结果，以及一个与结尾一致的情绪变化。成片不能只复述集数进度；注释要帮助观众看懂“接下来会发生什么、为什么会发生、结果会怎样”，但不能提前讲完整集。

## 无语音高能串联模式

本技能默认采用“高能片段串联完整故事”模式：先从素材中找出冲突爆发、局势升级、反击或证据、结果落地等关键画面，再根据完整故事需要加入起因、人物关系、动作因果和结果承接等过渡片段。过渡片段可以充分加入，不以“最少”为硬性要求，但不能为了凑时长加入无关内容。故事可以按叙事顺序重排，但每个源时间段只能使用一次；所有片段之间都不得发生源时间重叠，也不因为片段是高能就允许重复播放。片段按成片顺序直接剪切拼接，不做重复钩子、回放式预告或重叠叠化。

每个高能片段必须在剪辑计划中标记 `high_energy: true`，并通过 `annotation_ids` 绑定至少一条落在该片段成片时间内的单行剧情注释。注释只负责告诉观众冲突将如何升级或结果是什么，不替代关键画面；不生成中文解说语音，不把注释烧录进视频。

本技能的注释时序以成片画面为唯一依据：注释必须等对应的原剧对白、动作或结果已经开始出现后再显示，不为了“承上启下”提前预告下一段剧情。原视频已经提供过渡镜头时，优先让画面和原声完成承接，注释只在承接画面中补充必要信息；不得在上一段结束后、下一段画面尚未给出依据时提前显示。高能动作的注释应从动作开始附近出现，并覆盖动作过程或紧接着的结果。

## 文件输出规则

所有最终文件统一放在 `L:\workspace\yinghe-shijie\videos\exports\短视频\<原视频文件名>` 下。成片、剧情注释 JSON、注释旁车 SRT、编辑计划、封面和需要交付的其他文件不得散落在 `outputs/` 或其他目录。

## 默认制作模式

- `annotation_only` 必须为 `true`。
- 计划中不写中文配音 `narration.segments`，不调用 `produce_short_video.py`，不生成中文 MP3。
- `mix.source_audio_mode` 使用 `keep_source`，`source_volume` 使用 `1.0`；保留原剧完整音轨。
- 默认不设置 `background_music`。用户明确要 BGM 时，另行确认它不会遮挡对白，并单独记录版本。
- `burn_captions` 必须为 `false`；注释不烧录进 MP4，只通过 `jianying_assistant` 写入剪映草稿。计划可保留 `caption_mode: "plot_summary"` 作为注释格式标记，始终忽略 `subtext`。
- 每个注释通常显示 2—4 秒，只保留一条短句；注释之间不要连续堆叠。6—8 分钟成片通常使用 12—24 条，只有画面确有信息变化时才增加。文字应是接下来剧情的简介，不是“人物名 / 章节名 / 主标题 + 副标题”，也不是逐句抄写原对白。
- 注释目标是画面上方安全区，避开原字幕、人物脸部和关键动作；当前 `jianying_assistant` 插件使用固定变换位置，写入草稿后必须在剪映中检查并手动调整位置，需要竖屏时先检查裁切。

## 视频号选题方向

将视频号作为默认发布场景时，优先做年代家庭伦理剧解说，围绕家庭、婚姻、赡养、兄弟姐妹、返乡、婆媳、遗产、重组家庭和女性成长，选择观众能马上代入、也适合转发讨论的一个具体矛盾。

候选剧情优先级：

1. 一家人因房子、赡养、婚姻或责任分配被迫作出选择，且本条素材有明确结果。
2. 八九十年代或跨年代生活变迁中的亲情、手足关系、返乡与个人成长。
3. 女性从忍让到作出决定，或重组家庭重新建立边界；不得把羞辱、性别对立或苦难消费当作钩子。
4. 单集或一段素材已经形成“误会/危机 → 升级 → 真相或选择”的完整冲突链。

第二测试方向为古装神话、民间传奇与历史传奇。优先因果、孝道、命运选择、民间人物和局势反转；不要只依赖“神仙打架”“大结局”或角色名做标题。

默认不优先纯甜宠、都市偶像职场和人物关系过多的权谋线，除非该段能压缩为一个清楚的家庭或命运冲突并通过评分门槛。

标题和第一条注释从具体问题、结果或立场冲突切入，不以“第几集发生了什么”作为唯一钩子。注释示例只能作为结构参考，必须由素材、字幕和画面证实，不能把示例当成真实剧情。

## 人性问题、观点与情绪价值

不得把短视频做成“第几集发生了什么”的流水账。每条计划必须先写出一个能被本条素材回答的人性问题，并让标题、前 8 秒注释和结尾共同回答它。集数、剧名和角色名只用于背景和检索，不得充当唯一卖点。

解说观点仍然保留，但改写为剧情注释能够承载的判断：观点必须建立在素材中可见的行为、台词、关系变化和实际后果上；区分剧情事实、分析和开放判断，不把未说出口的动机或后续命运当成事实。

每条成片完成三层：

1. 观点落点：在阶段性结果之后，用一条简短注释说明这个选择暴露了什么责任、边界或代价。
2. 可讨论的冲突点：在结尾注释或发布简介中提出具体问题，不靠辱骂、性别对立或编造反转制造评论。
3. 情绪价值：让观众获得被理解、释然、警醒、替角色不值、重新看懂选择或意识到关系边界等具体感受。

剧情卡先填写：

```text
本条核心冲突：<谁为了什么，陷入什么困境>
本条人性问题：<一个由本条剧情回答的具体选择、关系或代价>
开头立场钩子：<前 2 秒出现的冲突判断或尖锐问题>
解说立场/观点：<基于素材事实，对选择、责任、边界或代价的判断>
可讨论的冲突点：<观众可以从不同角度讨论的具体问题>
观众情绪价值：<看完后获得的情绪感受或认知变化>
观众最早应知道的结果：<反转 / 代价 / 关键选择>
人物关系：<角色名或身份 + 与主角的关系>
起因 → 升级 → 转折 → 当集落点：<各一句>
不能断言的内容：<未在素材或字幕中证实的动机、后续剧情>
```

如果无法写出清楚的人性问题，或素材只能复述剧情进度，则不选该段；改选冲突和结果更完整的素材。

## 边界与输入

1. 以平台影视项目实际展示的可用片单和当前授权状态为唯一依据。不得下载或绕过付费、登录、DRM、平台权限；不移除版权标识，也不声称剧集归自己所有。
2. 只使用当时可免费或可供会员观看的内容；不得使用额外付费内容，包括“超前点播”“云首发”等。
3. 成片目的仅限介绍、宣传、讨论相关影视项目的自行使用；不要用于无关叙事、商品导流或冒充官方内容。
4. 不得形成可能实质替代正片传播的效果。每条只讲一个可独立成立的冲突链，保留观看正片所需的关键过程与整体体验。
5. 遵守当前平台和授权规则规定的单条时长上限。没有明确硬性上限时，时长由完整冲突链决定，不为了凑时长添加注释，也不为了追求短小删除理解结果所需的过程。
6. 需要原始视频与对应字幕。只有截图、链接或剧情梗概时，只交付剧情注释文案和剪辑计划，不虚构时间码或成片。
7. 原剧对白、环境声和动作声是主要叙事轨道。不要用中文音频复述对白，不把原声静音，也不要让注释遮挡原字幕或关键表情。

## 制作流程

1. 运行 `../yinghe-short-video/scripts/prepare_review_assets.py`，检查时长、字幕提示和联系表，只根据用户提供的本地素材选镜头。
2. 先建立剧情卡，再扫描高能片段。先锁定一个能落到阶段性结果的冲突爆发点，再向前找起因和升级，向后找反击、证据或结果；人物多、剧集长时，只讲一个冲突链，不把全剧人物和支线塞进一条短视频。
3. 为高能候选片段评分：冲突爆发 25%、结果或反转 25%、画面证据 20%、人物关系清晰 15%、与前后片段的因果衔接 10%、注释可读性 5%。先选能组成“爆发 → 升级 → 反击 → 结果”的核心片段，再按故事完整性加入必要过渡，不按原片顺序机械截取，也不为了凑时长加入重复镜头。
4. 默认使用源片画幅和 `layout: "source"`。只有用户或平台明确要求竖屏时，才使用 `contain_blur` 或 `fill_crop`；无论故事需要多长，都不得超过平台和授权规则上限。
5. 按“爆发点先抓住观众，再补原因，最后交付结果”安排直接剪切的画面序列和注释：
   - 0—2 秒：显示最强冲突或结果提示，必须由素材证实。
   - 2—8 秒：用画面、人物关系或原对白证明第一条注释，不要连续铺满文字。
   - 中段：根据实际剧情信息推进起因、选择、阻碍或新信息，通常每 4—8 秒出现一条，但不为凑节奏硬塞注释；每条注释都必须对应已经开始发生或正在给出证据的画面。
   - 后段：交付本条承诺的反转、代价或阶段性结果。
   - 结尾：等结果画面或原声对白出现后再说明结果，再落下观点，最后提出具体讨论问题或下一条悬念；不把“下一集见”当作唯一结尾。
   - 若为增强开头而重排片段，仍须保证每个源时间段只出现一次；不得把后段高能片段先放一遍、后面再按原顺序放一遍。
6. 写一份“剧情注释时间线” JSON，使用 `source_subtitle`、`video_duration` 和 `segments` 字段；每个 segment 只有 `start`、`end` 和一条可直接显示的 `text`。不要写 `english_text`，不要为注释生成 TTS 字段。
7. 调用现有注释脚本的单行剧情模式：

   ```powershell
   python "L:/workspace/yinghe-shijie/skills/generate-narration-audio/scripts/build_timeline_annotations.py" `
     --timeline "<剧情注释时间线.json>" `
     --output "<输出目录>/<topic>_annotations.json" `
     --target-video "<输出 MP4>" `
     --format plot_summary
   ```

   该模式只填充 `text`，强制 `subtext` 为空，并使用 `style: "arrow_callout"`，避免 `jianying_assistant` 把文字处理成带方括号的标题卡。生成后运行 `validate_annotations_json.py`。如果原始时间线文本不是剧情简介，先重写时间线，不要把技术标签或整段对白直接显示出来。
8. 计划必须包含 `annotation_only: true`、`annotation_file`、`caption_mode: "plot_summary"`、`burn_captions: false`、`write_subtitles: false`，并使用：

   ```json
   "mix": {
     "source_audio_mode": "keep_source",
     "source_volume": 1.0,
     "narration_volume": 0.0,
     "music_volume": 0.0
   }
   ```

   计划不得包含 `narration.segments`、中文配音路径或默认 BGM；建议同时写入：

   ```json
   "edit_rules": {
     "selection_mode": "high_energy_story_chain",
     "clip_order": "story_order",
     "source_reuse": false,
     "source_overlap": false,
     "allow_transition_clips": true,
     "direct_cut": true,
     "burn_annotations": false
   }
   ```
9. 先运行 `../yinghe-short-video/scripts/validate_preflight_review.py --plan <plan.json>`。预检必须确认：剧情在前 8 秒可懂；每条注释是单行剧情简介；没有主副标题结构；文字没有遮挡原字幕、脸和关键动作；标题、注释、简介承诺同一个结果；没有中文音频；原剧声音保持可辨识且不被压低；所有片段源时间不重叠、不重复；每个高能片段都有对应注释。
10. 不在本技能中用 FFmpeg 把注释烧进 MP4。需要检查剪辑顺序时，只能生成无文字的清剪版；正式注释保存在 `<annotations.json>`，打开 `L:\workspace\jianying_assistant` 的“视频注释插入”功能，选择对应剪映草稿和该 JSON 文件；如果注释时间已经是草稿时间线，时间偏移保持 `00:00:00.000`。插件会在 `subtext` 为空时只插入单行文字，但当前使用固定变换位置；建议先备份草稿，再在剪映中把文字移动到上方安全区，确认没有遮挡原字幕、人物脸和关键动作。
11. 在剪映中逐段抽检并完整观看。确认剧情在前 8 秒可懂、注释与画面同步、原对白没有被替换、文字没有遮脸或遮原字幕、注释之间没有拥挤、画面裁切正确。通过后再由剪映导出 MP4；不要把插件写入前的原始草稿当作最终成片。

## 复盘后的影视剧情剪辑要求

- 先确认最终剧名、集数、授权状态和素材来源；不把不同电视剧混用。
- 高能片段不能只截一句刺激台词。保留完整对白、必要反应和紧接着的后果，不能突然切掉维持因果的关键动作。
- 所有片段的源时间段都不得相互重叠或重复，包括高能片段；高能片段只代表故事节点，不是重复播放的例外。每个高能片段必须填写 `annotation_ids`，绑定落在该片段成片时间内的剧情注释。
- 在高能画面、过渡画面或下一段冲突已经开始并给出依据时，可用一条简短注释完成承上启下；不得在画面和原声之前提前预告，不能用注释替代原视频已有的过渡镜头。
- 所有注释时间都按剪辑后的成片时间计算，不得直接套用源片时间码；高能注释必须落在对应高能片段的成片时间范围内，并从实际动作或对白开始附近显示。
- 逐段建立“剧情注释—画面—原声”对应表。重排片段后重新检查注释时间、画面顺序、原剧对白和字幕是否一致。
- 原剧对白尽量保留完整句或完整语义段；注释只提供理解线索，不与对白争夺注意力。
- 注释应使用自然中文，少量幽默必须合语境；不写“震惊”“太狠了”“全网泪目”等空泛词。
- 代理时间线经过拼接或非线性排序时，按每个实际片段建立“代理时间—原片时间—字幕—成片时间”对应表，不能把全局 SRT 时间直接套到成片；同一源时间段只能对应一个成片片段。
- 不得把后段高能预告插入正常剧情后又完整重复一次；如果高能片段已经作为开头使用，后面只补未使用的起因、升级和结果片段。

### 复盘固化的成功版模板

- 每条只讲一条能独立成立的冲突链，优先按“具体起因 → 危机或惩罚 → 升级 → 规矩/阻碍 → 主角利用现场道具或动作改局 → 阶段性结果 → 下一关钩子”组织。不要把同一集的其他支线、人物线或重复判断混进来，也不为了凑时长补无关镜头。
- 开头 0—2 秒直接给出本条最强冲突或结果证据；如果高能画面已经作为开头使用，后面只补未使用的起因、升级和结果，不再按原片顺序重复该画面。
- 按故事时间线直接剪切。允许加入原视频中的求饶、反应、规则说明、道具准备和结果承接等过渡镜头，但每个源时间段只使用一次，所有源时间段互不重叠；禁止回放式预告、重复钩子和重叠叠化。
- 高能镜头必须保留完整动作、关键反应和紧接着的后果，不只截一句刺激台词。每个高能镜头绑定至少一条注释，注释落在成片对应镜头内。
- 注释统一使用带双引号的单行剧情简介，例如“她没有硬顶，而是先用规矩拦住惩罚”。一般 2—4 秒一条，平均 4—8 秒出现一个信息点；只有画面确有新动作、新证据、新关系或新结果时才增加。注释从动作、对白或结果开始附近显示，不提前预告；承上启下优先交给原视频画面和原声完成。
- 结尾先让结果画面或原剧对白落地，再追加一条基于已出现对白、动作或下一关明确线索的短钩子，吸引观众继续看下一集；不能只写“下一集见”，也不能编造未在素材中出现的悬念。
- 全片保持原剧对白、环境声和动作声；不生成中文解说音频、不加 BGM、不烧录注释。正式注释通过 SRT/`annotations.json` 写入剪映草稿，最终检查注释与画面、原声同步。

### 参考高数据视频的可迁移手法

- 片头不铺背景、不从剧名或集数开始，前几秒直接进入具体冲突、危险动作或结果证据；第一条注释同步给出一个有画面依据的判断或问题。
- 全片只回答一个普通观众能马上理解的问题。每个镜头都必须推进起因、升级、反击、证据或结果中的一环；与主线无关的支线、重复判断和只为凑时长的漂亮镜头全部删除。
- 注释使用短句判断，不写流水账或逐句翻译台词。判断必须紧贴人物正在做的动作、正在出现的反应或已经给出的证据；先让画面证明，再用注释补充“为什么”和“接下来会怎样”。
- 用连续的视觉证据串起故事。优先让衣裳、手、脚、鞋底、香囊、花纹、工具、门庭或其他现场道具逐步承担信息，让每个新动作或新反应自然推动下一条注释，而不是靠文字连续解释。
- 节奏以“每 4—8 秒出现一个有效信息点”为参考，不追求每秒切镜头。高能动作保留完整过程，原剧反应和过渡镜头负责呼吸；注释通常显示 2—4 秒，避免连续堆满屏幕。
- 开头钩子和结尾钩子各自承担不同任务：开头提出冲突，结尾在阶段性结果落地后留下下一关的具体问题；不把同一高能片段前后重复播放，也不把“下一集见”当作唯一悬念。
- 只借鉴参考视频的开头、节奏、单冲突结构、短句判断和评论引导思路，不复制其文案、素材、平台界面、评论区、账号水印或未经核实的观点；任何手法都必须重新用当前电视剧的画面和字幕验证。

## 封面规则

默认参考普通短视频技能 `yinghe-short-video` 的封面生成逻辑制作三张原创封面，至少覆盖 16:9、4:3 和 9:16；不等待用户单独提醒。正式封面默认不直接使用源片或成片截图，除非用户明确确认使用官方物料。封面底图提示词必须来自已核验的剧情冲突、标题和注释，只保留一个清晰主体、高对比和足够留白；电视剧题材的主体优先使用手、脚、衣裳、香囊、鞋底、花纹、工具、门庭或场景等剧情象征，不生成可识别演员脸、仿真人脸、伪造剧照、误导性剧情画面、Logo 或水印。

- `cover_headline` 和 `cover_subhead` 使用已核验的最强冲突和结果提示，不机械复制平台标题；封面文字后期叠加，禁止让图像模型直接生成中文。封面可以使用短标题加一句结果提示，但不能把剧情注释整段搬上去。
- 16:9 横版（建议 `1920x1080`）：主体放左侧或左下，右侧保留深色标题区和一种克制的强调色；使用 `skills/yinghe-short-video/scripts/add_cover_title.py --layout right` 后期叠加准确文案。
- 4:3 标准封面（`1440x1080`）：单独检查主体和标题区是否完整，主体放左侧或左下，右侧或上方保留标题区；使用与其他规格一致的核验文案，文件名为 `<topic>_封面_4x3_设计版.png`。
- 9:16 竖版封面（`1080x1920`）：即使视频保持 16:9，也要单独制作竖版封面；主体放中下部，上方留标题区，文字位于中央 80% 安全区。主标题通常 4—6 个汉字，单行副标题不超过 6—8 个汉字；不使用长箭头链、密集名词列表或贴边文字。使用 `add_cover_title.py --layout portrait`，不要把横版长文案硬塞进竖版。
- 三张封面分别检查：比例和分辨率、主体是否被裁切、文字是否拥挤或贴边、标题区对比度、关键剧情象征是否被遮挡，以及是否出现可识别演员脸、伪造剧照、Logo 或水印。只有用户明确要求跳过封面时才不制作。

## 交付

每条制作交付：剧情注释 JSON、剧情注释时间线 JSON、编辑计划、B站/抖音/快手/小红书四个平台标题和可直接粘贴的完整简介，以及三种封面版本/风格。使用 `jianying_assistant` 写入并由剪映导出后，再补交最终 MP4 和导出后的草稿检查结果。最终回复中说明剧名/集数、核心冲突、时长、作品类别、原声保留策略、注释数量、当前片单/授权确认结果及适用的时长上限。不要交付中文解说 MP3，也不要声称生成了中文配音。
